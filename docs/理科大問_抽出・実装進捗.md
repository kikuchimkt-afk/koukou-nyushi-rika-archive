## 判定の意味

- **完了**: 依頼対象年度について、対象学年・分野の独立大問を調査し、抽出、PDF目視監査、SCIENTIA実装、GitHub Release登録、本番確認まで終えている。
- **実装済み**: `data/archive.generated.json` に収録され、PDFと画像プレビューが公開されている。
- **補充選定済み**: 問題数のバランスを取る目的で選定・実装したもの。年度内の該当大問をすべて調査したという意味ではない。
- **要監査**: アプリに収録がなく、該当問題が0題だったのか、抽出が未完了なのかを既存記録だけでは確定できない。
- 年度別表の `—` は「実装0題」を示す。**監査済み0題を意味しない**。

共通ルール:

- 小問集合は原則として除外する。
- 単元判定は解答・解説冒頭の太字見出しを第一の根拠とし、大問の全設問も確認する。
- 中2抽出では中1内容の混在は許容するが、中3内容が混在する大問は除外する。
- 問題、解答用紙、正解、解説のページレイアウトと監査基準は、別リポの `docs/高校入試_大問抜粋PDF作成・ページレイアウト手順.md` を正本とする。

## 再開チェックリスト

1. この台帳とSecondBrainの同期台帳を読む。
2. 両リポジトリで `git status --short` を確認し、既存の作業を消さない。
3. 上表の「次回の安全な再開位置」から年度・学年・分野を決める。
4. 対象県の問題、解答用紙、正解、解説の原本を確認する。
5. 太字見出しと全設問を見て、対象大問と除外理由を記録する。小問集合は除外する。
6. 問題 → 解答用紙 → 正解（全問） → 解説（対象大問）の順でA4 PDFを作る。
7. 200dpi以上の全ページ画像と240dpi以上の境界拡大画像で、見切れ、不要ヘッダ、隣接大問、無駄な空白を目視監査する。
8. 最小実効解像度600dpi以上、縮小率85％以上、全ページA4を機械確認する。
9. 最終版フォルダへ確定し、SCIENTIAのプレビューとカタログを再生成する。
10. `npm.cmd run check-content`、`npm.cmd run build`、`npm.cmd run check-merge` を実行する。
11. ReleaseへPDFを登録し、コミット・push・Vercel本番表示・単一PDF結合を確認する。
12. この台帳の件数、年度、再開位置、基準コミットを更新し、SecondBrainへ同期する。

## 台帳の更新ルール

- 対象年度を調査して該当が0題だった場合も、`監査済み0題` と明記する。
- 未調査の0件は `—（未監査）`、調査済み0件は `0（監査済み）` と区別する。
- 「全件完了」と「バランス調整の補充選定」を混同しない。
- 採用題だけでなく、除外した大問と理由も年度別監査記録に残す。
- 問題数とページ数は `data/archive.generated.json` から再集計し、手計算だけで更新しない。
- PDF監査、アプリ実装、Release登録、本番確認の4段階がそろってから「完了」とする。
